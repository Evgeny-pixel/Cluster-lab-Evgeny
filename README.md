        Перед любыми действиями советую полностью прочитать данную инструкцию. Выполнение скрипта deploy.sh позволит вам развернуть кластер из сервера приложений, мониторинга и сборщика логов (app-server, mon-server and log-server). Для работы необходимы 4 виртуальные машины на базе Ubuntu server (3 кластер сервера и 1 бастион сервер). Бастион сервер - через него будет выполняться вся автоматизация, так как он связан с другими серверами по внутренней сети VM. Cервер приложений, на нем будут развернут Wordpress, работающий через веб сервер Nginx, а так же база данных MySQL, подключенная к Wordpress. Cервер мониторинга - развернуты Zabbix и Prometheus + Grafana + Alertmanager. Он будет собирать системные метрики, такие как процессор, озу, диски, сетевые интерфейсы и тд со всех серверов кластера. Так же настроены правила оповещения алертов в телеграм по базовым метрикам: доступность хостов, высокая загрузка процессора, памяти, недостаток дискового пространства, доступность базы данных MySQL и доступность nginx. Сервер логов - стек ELK (elasticsearch, logstash, kibana), будет выполнять сбор логов с приложений app server. 

        Для подготовки к запуску скрипта выполните следующие действия. Установите 4 виртуальные машины в Virtual Box на базе Ubuntu server 24.04.4 со следующими характеристиками: минимум 2 ядра, 4 гб озу и диск 50 гб, можно характеристики лучше но не хуже. !!!!! ВАЖНАЯ ИНФОРМАЦИЯ !!!!!. Необхожимо выполнить полноценную установку только первой машины, например бастион сервера. При установке обязательно поставьте пункт "Install openssh-server". После полноценной установки необходимо выполнить полное клонирование первой машины с генерацией нового MAC адреса для всех оставшиеся серверов три раза. Это необходимо для того, чтобы имя и пароль пользователя полностью совпадали с тем, что вы вводили при первой полноценной установке системы. То есть вы должны установить полноценно bastion-server, а затем клонировать его, но с другим названием, например app-server и сгенерировать новый MAC. Так необходимо сделать 3 раза для каждого сервера в кластере. По итогу у вас должно получиться 4 сервера (bastion-server, app-server, mon-server, log-server). После настройте каждую машину в Virtual box. Bastion-server: измените первый сетевой интерфейс с NAT на сетевой мост, чтобы бастион сервер получил ip адрес вашей локальной сети и мог общаться с вами напрямую. Далее выберите адаптер 2, поставьте галовку чтобы активировать его и выберите тип внутренняя сеть. Имя можете дать любое, например "cluster-lab". Это нужно для одновременной связи бастион сервера с вашей локальной сетью и с внутренней сетью кластера. App-server: добавьте 2 дополнительных жестких диска обьемом в 30 гб а так же активируйте второй сетевой адаптер с типом виртуальная сеть и выберите ту сеть, которую прописали в bastion server, например cluster-lab, первый адаптер оставьте в NAT. На mon и log servers активируйте второй адаптер и так же выберите виртуальная сеть с вашим названием, первые адаптеры не трогаем.

        Далее необходимо настроить сеть на всех серверах. Ip-адреса будут следующими: bastion-server - 172.16.0.1/24, app-server - 172.16.0.2/24, mon-server - 172.16.0.3/24, log-server - 172.16.0.4/24. Запускаем каждую виртуальную машинy. Так как по умолчанию на Ubuntu сеть управляется через Netplan, то мы будем использовать его, но можно и настроить через NetworkManager. Выполните на каждом сервере команду "ip a" и посмотрите на название третьего интерфейса, обычно это enp0s8, это наш активированный адаптер 2 с виртуальной сетью. Необходимо задать ему ip адрес и активировать интерфейс. Для этого выполните следующие команды на каждом сервере: "sudo nano /etc/netplan/99-lab-inet.yaml". 
    Затем пропишите в файлах на каждом сервере следующее:
    
network:
  version: 2
  ethernets:
    enp0s8:
      dhcp4: false
      addresses:
        - 172.16.0.X/24

        После сохраните каждый файл и выполните на всех серверах команду "sudo netplan apply". Проверьте доступность каждого хоста с bastion-server: "ping 172.16.0.2", "ping 172.16.0.3", "ping 172.16.0.4". Если пакеты идут значит виртуальная сеть настроена правильно. Так же проверьте связь bastion-server с вашим хостом, для этого на бастионе выполните "ip a" и посмотрите на ip-адреc интерфейса enp0s3 (если вы настраивали адаптеры в VirtualBox по инструкции то название интерфейсов должно совпадать). Далее узнав адрес, выполните команду "ping address" на ВАШЕМ ХОСТЕ (основной операционной системе на которой у вас установлен VirtualBox). Вместо address напишите адрес вашего интерфейса на bastion-server, чтобы проверить доступность бастион сервера. Если пакеты идут, значит сеть между бастионом и вашим хостом настроена правильно. Затем на bastion-server выполните "sudo apt install -y ansible sshpass".

        Теперь мы имеем полностью готовый кластер для деплоя. Кластер находится в закрытой от нас внутренней сети, а вся настройка будет происходить через jump-хост (наш bastion-server), к которому мы имеем прямой доступ. Перейдите в директорию где лежит папка lab на вашем хосте и выполните следующую команду: "scp -r lab user@address:/home/user/". Вместо user и address напишите пользователя, которого создавали и ip адрес интерфейса enp0s3 вашего бастион сервера. При первом подключении ssh просит добавить отпечаток сервера, вводим yes. Затем введите пароль от пользователя. Таким образом вы скопируете папку lab со всем содержимым в домашнюю директорию вашего пользователя на бастион сервер. После копирования подключитесь по ssh к бастион серверу, выполнив "ssh user@address", и подставляя свои данные. После чего для запуска деплоя выполните строго следующую команду:
    cd ~/lab/deploy-cluster/ && ./deploy.sh

        После запуска введите пароль для создаваемых ssh ключей, если хотите без пароля то просто нажимайте enter. Будьте внимательнее, не пропустите этап с вводом пароля от пользователя и данными телеграм. После генерации ключей введите пароль пользователя, затем токен вашего телеграм бота, после введите ваш чат id. Чтобы создать телеграм бота воспользуйтесь @BotFather в телеграм, после создания бота он отправит сообщение об успешном создании и покажет его токен, чтобы узнать свой чат id используйте @my_id_bot. После работы скрипта у вас будет готовый развернутый кластер из сервера приложений, мониторинга и сборщика логов. Снова зайдите в консоль вашего хоста и напишите команду "ssh -D 1080 user@address -N", user и address так же от вашего бастиона, после чего у вас откроется динамический проброс портов вашего хоста во внутреннюю сеть кластера. Терминал на время работы с кластером не закрываем и просто держим в фоне. Вам остается лишь в настройках браузера активировать прокси и выбрать пункт "Использовать заданные параметры". В них найдите SOCKS прокси и запишите локальный адрес 127.0.0.1, порт 1080. Это означает, что весь трафик браузера будет перенаправляться в локальный 1080 порт, который пробрасывает нас в бастион сервер, то есть через него будет осуществляться и выход в интернет, и доступ к внутренней сети кластера. После настройки прокси наберите в адресную строку ip адрес нужного сервера и порт. Подсказки: Wordpress - 172.16.0.2:80, Prometheus web - 172.16.0.3:9090, Grafana - 192.168.0.3:3000, Kibana - 192.168.0.4:5601. Данные для MySQL: пароль для root - "root9999", имя пользователя - "wp_user", пароль пользователя - "1111", название базы данных - "wordpress".

        Before proceeding, I recommend reading this entire manual. Running the deploy.sh script will allow you to deploy a cluster consisting of an application server, monitoring server, and log collector (app-server, mon-server, and log-server). This setup requires four Ubuntu Server-based virtual machines (three cluster servers and one bastion server). The bastion server will handle all automation, as it is connected to the other servers via the internal VM network. The application server will host WordPress running through an Nginx web server, as well as a MySQL database connected to WordPress. The monitoring server will host Zabbix, Prometheus, Grafana, and AlertManager. It will collect system metrics, such as CPU, RAM, disks, network interfaces, and so on, from all servers in the cluster. Telegram alert rules for basic metrics are also configured: host availability, high CPU and memory load, low disk space, MySQL database availability, and Nginx availability. The log server, an ELK stack (elasticsearch, logstash, kibana), will collect logs from the app server applications.

        To prepare to run the script, follow these steps: Install four virtual machines in Virtual Box running Ubuntu Server 24.04.4 with the following specifications: at least two cores, 4 GB of RAM, and 50 GB of disk space. Better, but not worse, is acceptable. IMPORTANT INFORMATION!!!!!. Only the first machine, such as a bastion server, needs to be fully installed. During installation, be sure to select the "Install openssh-server" option. After the full installation, you must fully clone the first machine and generate a new MAC address for all remaining servers three times. This is necessary to ensure that the username and password exactly match what you entered during the first full installation of the system. This means you should install the full bastion server, then clone it, but with a different name, such as "app-server," and generate a new MAC address. This must be done three times for each server in the cluster. You should ultimately have four servers (bastion-server, app-server, mon-server, and log-server). Then, configure each machine in Virtual Box. For the bastion server, change the first network interface from NAT to bridged so that the bastion server receives an IP address from your local network and can communicate directly with you. Next, select adapter 2, check the box to activate it, and select the internal network type. You can name it anything you like, such as "cluster-lab." This is necessary to simultaneously connect the bastion server to both your local network and the cluster's internal network. App-server: Add two additional 30GB hard drives and activate the second network adapter with the virtual network type and select the network you defined in bastion server, for example, cluster-lab. Leave the first adapter in NAT. On the mon and log servers, activate the second adapter and also select a virtual network with your name. Leave the first adapters alone.

        Next, you need to configure the network on all servers. The IP addresses will be as follows: bastion-server - 172.16.0.1/24, app-server - 172.16.0.2/24, mon-server - 172.16.0.3/24, log-server - 172.16.0.4/24. Start each virtual machine. Since the network is managed by default on Ubuntu via Netplan, we will use it, but you can also configure it via NetworkManager. Run the "ip a" command on each server and look at the name of the third interface. It's usually enp0s8, which is our activated adapter 2 with the virtual network. You need to assign it an IP address and activate the interface. To do this, run the following commands on each server: "sudo nano /etc/netplan/99-lab-inet.yaml".
    Then, add the following to the files on each server:
    
network:
  version: 2
  ethernets:
    enp0s8:
      dhcp4: false
      addresses:
        - 172.16.0.X/24

    !!!!!INSTEAD OF X, WRITE A NUMBER IN ACCORDANCE WITH THE SERVER NAME, AND ALSO KEEP STRICT INDINCES AS IN THE EXAMPLE!!!!!

        Afterwards, save each file and run "sudo netplan apply" on all servers. Check the availability of each host from the bastion server: "ping 172.16.0.2", "ping 172.16.0.3", "ping 172.16.0.4". If packets are passing, the virtual network is configured correctly. Also, check the connection between the bastion server and your host. To do this, run "ip a" on the bastion and look at the IP address of the enp0s3 interface (if you configured the adapters in VirtualBox according to the instructions, the interface names should match). Next, find the address, run the "ping address" command on YOUR HOST (the main operating system on which you have VirtualBox installed). Replace "address" with the address of your interface on the bastion server to check the availability of the bastion server. If packets are passing, the network between the bastion and your host is configured correctly. Then, on the bastion server, run "sudo apt install -y ansible sshpass."

        Now we have a fully deployable cluster. The cluster is located on a private internal network, and all configuration will occur through a jump host (our bastion server), which we have direct access to. Navigate to the directory containing the lab folder on your host and run the following command: "scp -r lab user@address:/home/user/." Replace "user" and "address" with the user you created and the IP address of your bastion server's enp0s3 interface. When you first connect, SSH asks you to add a server fingerprint. Enter "yes." Then enter the user's password. This will copy the lab folder and all its contents to your user's home directory on the bastion server. After copying, connect via SSH to the bastion server by running "ssh user@address" and substituting your credentials. Then, to start the deployment, run the following command:
    cd ~/lab/deploy-cluster/ && ./deploy.sh

        After launching, enter the password for the generated SSH keys. If you don't want to enter a password, just press enter. Be careful not to skip the step where you enter the user password and Telegram credentials. After generating the keys, enter the user password, then your Telegram bot token, and then enter your chat ID. To create a Telegram bot, use @BotFather in Telegram. After the bot is created, it will send a message confirming successful creation and display its token. To find your chat ID, use @my_id_bot. After the script runs, you will have a fully deployed cluster consisting of an application server, monitoring, and a log collector. Log into your host's console again and enter the command "ssh -D 1080 user@address -N" with the user and address from your bastion. This will enable dynamic port forwarding of your host to the cluster's internal network. Keep the terminal running in the background while working with the cluster. All you need to do is enable the proxy in your browser settings and select "Use specified parameters." Find the SOCKS proxy and note the local address 127.0.0.1 and port 1080. This means all browser traffic will be redirected to local port 1080, which forwards us to the bastion server. This means it will be used for both internet access and access to the cluster's internal network. After configuring the proxy, enter the desired server's IP address and port in the address bar. Suggestions: WordPress - 172.16.0.2:80, Prometheus Web - 172.16.0.3:9090, Grafana - 192.168.0.3:3000, Kibana - 192.168.0.4:5601. MySQL data: root password is "root9999", username is "wp_user", user password is "1111", database name is "wordpress".
